# Project guidance

Read `PROJECT_TRUTH.md` before changing this project. It records the user's confirmed design, current implementation, and unresolved decisions.

The current milestone is a playable falling-note prototype: title -> song select -> five lanes with song-time positions, chart speed, taps/holds/releases, Perfect/Good/OK/Miss judgments, score, and Perfect-only combo. Follow the user's simple reference layout and preserve replaceable backgrounds. Physical Bop It integration still needs direction. Latest confirmed timing is Perfect exactly 0 (no numeric tolerance), Good through 0.15, and OK through 0.4 seconds; point values and speed interpretation above 1x remain adjustable prototype choices documented in PROJECT_TRUTH.md. Keep the truth document updated when requirements or implementation change.

The main menu follows the reference in Assets/Art/menu: Hypik logo with a light-purple front and offset dark-purple copy underneath, black Start/Settings/Quit lettering over single offset white copies, and the oversized slowly clockwise-rotating pixelated-image.jpg background (not the high-resolution source). Use flat copies rather than surrounding outlines. All menus use arrow keys to navigate and Enter/Space to activate; mouse hover/click works with a small enlargement on title items. Start opens song select; Settings is deliberately a no-op; Quit exits a build or stops editor Play Mode. The title rebuild tool replaces title customizations, so use it only for an intended title rebuild.

Song select follows the latest image reference: static pixelated background, white Sportypo Back and centered heading, one rounded teal row with a white border, and the actual song title. The row launches gameplay directly; mouse or Enter/Space confirms, arrows navigate, and Back/Escape returns. Keep the title and gameplay intact when editing this screen. The user explicitly requested original demo 0-9 glyph exports even though those are promotional logos; do not silently replace them with real numerals. The character kit also contains white a-z sprites. The explicit song-select rebuild replaces its customizations only when intentionally invoked.

Read `HACKATHON_GUIDE.md` before changing behavior or architecture. The user wants this presentation and technical-understanding guide maintained as the project develops. Update it alongside `PROJECT_TRUTH.md` when implementation, controls, assets, timing, tests, or limitations change. Keep explanations grounded in the actual code, distinguish completed work from plans, disclose coding-tool assistance accurately, and never invent personal learning or team contributions.

Gameplay visual requirements: default to the supplied pixelated menu background while retaining level background overrides. Holds are opaque uniform-width/color rectangles. Center judgment art/details over the lanes and fade them over 0.6 seconds. Use black Hypik boopit artwork in the corner circle; pulse its scale from the song clock, level BPM, and optional first-beat offset. BPM must not move chart notes or change scoring.

Do not display keyboard labels beneath the lane targets. D/F/Space/J/K bindings are retained. UI menu move/submit is disabled during gameplay so Space cannot activate HUD buttons; restore it for title, song select, and results. MenuFlow owns the single Enter/Space submission action, avoiding duplicate confirmation or transitions from one key press.

Keep song select top-aligned and uniformly scaled to viewport width via SongSelectLayout. The user reconfirmed the compact Sportypo screenshot. An older loaded SampleScene without this component is upgraded once by the editor builder on import/return to Edit Mode; already upgraded menus are not rebuilt automatically.
